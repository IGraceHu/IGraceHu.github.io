IAJES Website Revamp

For my Senior Design Project at Santa Clara University, my team volunteered to revamp and improve the website of the International Association of Jesuit Engineering and Sciences (IAJES) schools.

Role: Lead UI Designer and Full-stack Developer
Tools: React, Tailwind CSS, Supabase, Figma, Adobe Illustrator
Team: Nicolas Gibson (UI Designer and Full-stack Developer), Anisha Malani (Front-end Developer), Justin Fan (Back-end Developer)

IAJES saw a need for an online platform where IAJES could share their resources and support their international academic community in collaboration and connection.

To address this need, we endeavored to create four main features in the new website:

Member Accounts
Modular Resources
Database Storage
Emailed Newsletter

Over the course of the project, I designed simple yet elegant assets and components for the team to use throughout the development process. Every layout, component, and interaction were designed with IAJES's mission and initial aesthetic in mind, and I brought my detail-oriented development and diligent work ethic to other areas of the project when needed.

User Experience

User experience is always a top priority of mine in design, especially since IAJES has such an established elegant aesthetic. I designed IAJES's styleguide with a seameless user and developer experience in mind. For the Popup and Multi-Select components, not only is user interactivity is the focal point, but developer implementation is also a concern because both components will be widely used across development.

Thus, the number one priority of these components is that the component would be functional, of course, and the number two priority is that the component would be enjoyable and easy to use.



Popups

Popups are a completely seperate element from the rest of the site, temporarily shifting user interactivity to a new location, which means that:

  1. The shift to and from the popup should smooth and seamless, easing the user to this new location and back.
  2. The site elements that are now in the background should not draw the user's attention and should remain unchanged as long as the user is within the popup.

For the first point, popups start out absent and un-rendered from the page. To open a popup, the popup must be first rendered, then animated in a smooth fade-in and maybe even a slide-in animation. To close a popup, the popup must be first animated, then un-rendered. Code executes very quickly, so it is not just a simple manner of rendering then animating. A timing function must come into play to ensure the transition is seamless.


As for the second point, the only gripe is with how browsers function. To disable background scrolling, the page's overflow must be disabled. However, elements with a disabled overflow lose their scrollbar, changing the width of the site viewport. This change of width is extremely noticable and irritating especially when there are many popups on the site. The disappearing scrollbar must be accounted for to ensure the transition is smooth.

Multi-Select

A multi-select allows a user to pick multiple options from a list. Unfortunately, the default HTML multi-select element is quite unintuitive and difficult for some users to utilize. A user would have to drag their cursor across their desired options, or hold CTRL to keep their desired options when picking other options.
The expected behavior of a multi-select would be:

  1. Clicking on an option selects the option, and clicking on a selected option deselects the option.
  2. Clicking on an option does not affect other options that have already been selected.
By using the multi-select as a controlled input with React and building a custom function to update the selected options when the user interacts with it, I built a multi-select input that fulfills both of those needs. Mobile devices and other touchscreen devices counteract this issue by using a extraneous and more accessible selection interface instead.
However, the mobile workaround results in multi-select having different behaviors on desktop and mobile. The desktop view would need a modified version of the default multi-select element to ensure a smoother and more accessible user experience, while the mobile view has no need of any modifications.
